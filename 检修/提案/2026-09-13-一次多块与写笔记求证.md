# 本轮工作单：一次多块阅读 + 写笔记求证

日期：2026-09-13
提出：交叉问题只能靠 Agent 自觉连读；写笔记只需先搜类似即可落盘
状态：说明书已改，待代码（先块 6，后块 7）
规格：以 `需求.md` 为准。本文是工作单，不另立规则。

## 1. 要加什么

加，不减。动两扇门的加深步，不新开工具。

1. **检索 / 阅读**（`需求.md` 4.1）  
   路标写到建议块；一次可点名多块；中文二字片。
2. **写笔记**（`需求.md` 4.4）  
   预览 → 求证 → 写入。`相符` / `部分不符` 必须先成功读过依据。

依据对照：`参考笔记.md` §4.1–4.2、§4.6–4.7；MCPVault `read_multiple_notes`（借 `string[]` + 部分失败，不借整文件无总顶、不借新工具）；ContextNest 只借总预算；OKF tokenize 不抄。

## 2. 动哪扇门

- `kb_search` / `kb_read`（仍是检索这一扇）
- `kb_write_note`（仍是写笔记这一扇）
- 调用日志（块 7 要查是否成功读过）

不动：入库、净化、自检闸门、书的正文、目录划分。

## 3. 对两条红线的风险

- **书不改：** 无。求证对不上只许标 `部分不符`，不能改书。
- **先抬头后正文：** 无倒退。检索仍无正文；一次多块必须点名，有块数顶和总字数顶。风险是把「一次多块」做成搜索带摘录——验收时禁止 search 返回章节正文。

## 4. 改法（实现时按这个，数字已写进规格）

块 6：

- 路标：一本一条，下列最多 2～3 个命中章名，身份可直接喂给 `kb_read`
- `targets: list[str]`，兼容旧 `target`+`part`
- 5 块 / 单块 8000 / 整次 24000
- 部分失败保留成功块；整本或没身份整单拒绝
- 中文：整句 + 空白/标点 + 连续汉字二字片，只打抬头

块 7：

- `action=verify`；create/update 必须同一份稿已 preview + verify
- 同一份稿 = 标题+介绍+正文；求证字段不算改稿
- 读过的判定：`检修/calls.jsonl` 里该身份成功 `kb_read`；窗口最近 100 条或 24 小时
- 抬头写入 `verify`、`sources`、`generated`
- Agent 怎么求证见 `docs/写笔记求证.md`，不能代替闸门

## 5. 怎么验收

块 6 先绿，再开块 7。清单见 `docs/计划.md` 本轮两块的「闸门」。最少包括：

- 交叉两本，一次阅读拿到两块，search 结果无正文
- 中文无空格问句能命中两边抬头
- 清单缺一块：2/3 成功
- 整本 / 空身份：整单失败
- 旧单块 `kb_read` 仍可用
- 不预览或不求证就 create：失败
- 没读过就 `相符`：失败
- `非事实` 不读可写入
- 想写进书：仍失败
