# docs/spike/ — 只放 Spike（探路），不放 Spec

三个词不要混：

| | Spike | 本轮 Spec |
|---|---|---|
| 干什么 | 搞清**一类问题**：根因、边界、对策能不能用 | 拍板后：**这一轮代码要做成什么样** |
| 产出 | 调研、真库只读实验、对照表 | 实现规格 + 闸门（pytest / 真库抽查） |
| 改 `mcp/` | **不许** | Spec 等人点头之后才许 |
| 进行中放哪 | **这里** `docs/spike/` | **`docs/本轮Spec.md`**（同时最多一份） |
| 做完 | 移到 `docs/归档/YYYY-MM-DD-spike-<主题>.md` | 移到 `docs/归档/YYYY-MM-DD-本轮Spec-<主题>.md` |

`需求.md` 是唯一一直有效的产品规格。Spike 和本轮 Spec 都是过程稿，做完归档，不再生效。

## 一轮怎么走

1. 从 `docs/问题.md` 选**一类**（不是一道题）。
2. **Spike**：在本目录写调研/实验。只读库、只读代码，不改实现。
3. 人点头后写 **`docs/本轮Spec.md`**。没有这份文件，不准改 `mcp/`。
4. 实现 + pytest + 真库抽查，追加 `检修/验收记录.md`。
5. Spec、Spike、实现计划整包进 `docs/归档/`。`docs/本轮Spec.md` 删掉，不留空壳。本目录没有进行中的稿就空着。

禁止对着单题写 Spike 或 Spec。
