## 0. 一句话

**资料室合同留下，检索引擎推倒重做。**  
入库、身份、阅读窗、六扇门、书不改、路标无正文——留。  
`retrieve.py` 靠闸门堆准度——扔。换成：编译厚地图 + 字段 BM25 + 章向量 + 融合收成 5 条路标。

不重复造轮子 = **不自研 BM25、不自研嵌入**；资料室合同没有现成产品能直接当这个 MCP 用，那一层自己留。

## 1. 需求锚（架构必须对上的）

| # | 需求（`需求.md`） | 架构怎么兑现 |
|---|---|---|
| D1 | Agent 本机资料室，不是 RAG 聊天框 | MCP 六扇门；搜索不灌正文 |
| D2 | 正本 Markdown；索引/向量不是正本 | `资料/` 是唯一正本；缓存可扔可重建 |
| D3 | 先路标后正文；最多 5 条；阅读另点名有顶 | 候选池 >5，**输出**仍 ≤5；`kb_read` 不变 |
| D4 | 一句问话要准 | 章名/别名加权 + 章向量补「说法对不上」 |
| D5 | 跨多本一次点齐 | 融合后允许多本；不为「只留一本」挤掉相关书 |
| D6 | 少占上下文 | 路标无摘录；重排若做，只看标题+地图，不看正文 |
| D7 | 入库配合检索；自然篇；可退整本 | 切块/退书/体检留下，地图编译加厚 |
| D8 | 中文长书；不上 jieba | 二字片预切 + FTS5 列权重 |
| D9 | 拉丁专名不在库则空 | 字面闸保留；向量不得单独把空题填满 |

## 2. 四层

```
人丢 PDF/EPUB
    → [入库] markitdown + 自然篇切块 + 编译地图
    → 资料/书/<slug>/{导读,地图,各块}     ← 正本
    → [索引缓存] FTS5 分列 + 章向量         ← 可扔
问句 → 别名只扩专名 → 字面召回 ∥ 向量召回 → RRF 候选池 → 最多 5 条路标
Agent 点名 → [阅读] 原文窗 ≤8000
```

### 2.1 正本层（几乎不动）

`资料/书/<slug>/` 一块一个自然篇，身份 `书/<slug>/<章>`。书不改正文。笔记仍一份一文件。

### 2.2 入库与管理（加厚地图，其余留）

收件箱 / 指定入库 / `withdraw` / 体检留下。

**合格地图**改为必须：

- 「能解决什么」覆盖主要非导航章名（含「第 X 节」，不能只抄一层标题）
- 可有 **别名**（林彪事件 → 批林整风）
- 可有 **主题词**（书指纹，20–40 词级，派生）
- 「建议从哪读」仍指向真实块身份
- 缺地图 / 章名覆盖过稀 → 未入完

地图仍由 Agent 编译、代码校验；工具不在检索路径里调大模型。

### 2.3 检索层（重做）

| 步 | 做什么 | 对应需求 |
|---|---|---|
| 扩写 | 只用地图/章名里的专名、别名；禁止扩「变化/发生/怎么回事」 | D4，防公共词 |
| 字面 | FTS5 分列：书名、章名、别名/地图、正文；`bm25()` 列权重，章名 > 正文 | D4 D8 |
| 语义 | 一块一向量，本地嵌入模型 | D4 说法对不上 |
| 融合 | RRF（或同等排序算术），候选几十条 | D5 |
| 收成 | 按书收成最多 5 条路标；标两路都中 / 仅字面 / 仅语义 | D3 D6 |
| 建议块 | 问句点名的篇名优先；地图依据块次之 | 实践论不被挤掉 |

**不做（本层 v1）：** 交叉编码器灌正文、HyDE 整句喂 FTS、512-token RAG 窗、问句类型路由。重排若加，只打「问句 ×（书名+地图+章名）」。

### 2.4 工具层（形状不动）

六扇门函数名可改、能力不能少。检索默认无正文。阅读顶不变。

## 3. 留下什么、扔掉什么

**留下（本仓库已做成、对需求有用）**

- 六扇门 MCP、失败交还
- markitdown 入库、自然篇、8000 窗、节名/`#n`
- `withdraw`、无文字层拒收、体检
- 写笔记预览→求证
- 身份字符串、路标无正文、Q/W/N 题集当对照（准的口径见下）
- 中文二字片（FTS 硬约束，不是土办法）

**扔掉（在错误基础上叠的）**

- 把「准」主要押在最长片 / LIT_GAP / aboutness 一串闸上（闸可以留作兜底，不再当引擎）
- 地图只写 5 条套话
- 候选池焊死在 5 再谈重排
- 「准 = 多一本相关书就整题 0」当作引擎目标（那是打分口径，要另议；引擎应能一次点齐多本）

---

## 4. 索引缓存

允许一份本机 sqlite（FTS + 向量）。入库/退书后失效或增量更新。删文件 = 从 Markdown 全量重建。stdio 长活可一次建完。

**不是**再引入一套独立向量数据库产品当正本。

---

## 5. 落地顺序（改代码前写 Spec）

1. 地图 schema + 校验（覆盖章名、别名段）——无向量也能抬 N7/N8 一类
2. FTS5 分列加权 + 候选池放大 + 融合收 5 格
3. 章向量 + RRF
4. 真库 Q/N/W 全组三维打分；准口径若要改须先改 `docs/验收标准.md`（人点头）

实现按 `docs/本轮Spec.md` 两段提交。没有打分新节不许归档。
