# 版本

> 人话记在这里。机器号在 `mcp/pyproject.toml` 的 `version`。两者必须一致。

## 怎么编号

**大.小.补**（SemVer），和「第几版资料室」对齐：

| 位 | 什么时候加 | 例子 |
|---|---|---|
| **大** | 产品合同或检索引擎换代（人说的「第 N 版」） | `2.x` → `3.0.0` |
| **小** | 同一代里做成一块能力（地图加厚、字段加权、章向量……） | `3.0.0` → `3.1.0` |
| **补** | 修 bug、改文档、闸门微调，合同不变 | `3.0.0` → `3.0.1` |

预发布：代码还没落地时，可以在号后面加 `-dev`（如 `3.0.0-dev`）。一做完、打过分，去掉 `-dev`。

**不要**用「第 3.1 版」这种口头号当 git tag。tag 写成 `v3.0.0`。

分支：一代一条长分支，`feat/v3-hybrid-retrieve`。小改在这条上往前推，不必每个 3.0.1 新开分支。

## 改号时做什么

1. 改 `mcp/pyproject.toml` 的 `version`
2. 在本文件「现在」表改一格，文末追加一行流水
3. 大版本：更新 `需求.md` 修订表；小/补：打分记录里写机器号即可
4. 落地打过分之后：`git tag v大.小.补`
