# 逻辑设计草案 · 库结构与检索调用

> 状态：**草案，等拍板。** 不是已锁实现。
> 日期：2026-09-12
> 依据：`需求.md` 已锁方向；`参考笔记.md` §4.1–§4.8、§5；本轮「Agent 只说想调研什么，披露和路由在工具内做」。
> 目标：合理、少轮次、少 token、少磁盘折腾。

---

## 1. 外面只看到什么

Agent 点名启用之后，检索侧主要就一扇门：

```
查询(我想了解什么)  →  一包「相关内容」+ 身份（还能再加深）
```

渐进披露、分类、文件夹、打开哪一章，**全部在 MCP 内做完**。外面不逛目录、不选库、不传「第几层」。

另外两扇门不动前面已过的结论：

| 谁 | 入口 | 干什么 |
|---|---|---|
| Agent | `查询` | 只说想调研什么 |
| Agent | `阅读(身份)` | 可选。查询不够时再要某一段。大多数时候不用 |
| Agent | `写入` | 交 Markdown 笔记（规则另述） |
| 人 / 代交文件的 Agent | 文件夹 `待入库/` | 丢 PDF/EPUB/MOBI；工具转换后源文件进 `归档/` |

故意做成「查询为主、阅读为辅」：外面少跳一轮（省延迟），工具内仍分层打开（省 token）。不是一问把三本书全文塞回去。

写入、待入库本草案只挂接，不展开细则。

## 2. 分类怎么做（省事的那种）

**学科不当文件夹。** 不要 `心理学/`、`生活/` 两套库再路由——资料会跨类，写回时不知道进哪间，检索还多一次分类错误。主题只用标签。

只按**资料形态**分两格（网页以后再说）：

| 形态 | 放哪 | 为什么单独一格 |
|---|---|---|
| 长资料（一本书、一篇长文，有内部结构） | `库/书/` | 要导读和按标题定位，不能当一张卡片 |
| 短资料（心得、推荐、摘要、一条笔记） | `库/笔记/` | 整份就可以读完 |

路由靠打分，不靠选文件夹：先看所有资料的标题 / 标签 / 一句话描述，再只打开赢了的那几份。库在几十到一两百份时，扫编目非常便宜，不必按学科切盘。

标签是自由的（`心理学`、`毛泽东`、`拖延`），不预设词表。转换或写入时带上就行，没有也仍能靠标题搜。

## 3. 文件夹

```
<本服务数据根>/
├── 待入库/          ← 人（或帮人搬文件的 Agent）只准放这里
├── 归档/            ← 已转换的源文件，不参与检索
└── 库/              ← 唯一检索范围，全是 Markdown
    ├── 书/
    │   └── <slug>/
    │       ├── 导读.md
    │       └── *.md          ← 按一级标题切开的章；切不开就一篇正文.md
    └── 笔记/
        └── <slug>.md
```

- `待入库/`、`归档/` **不进检索**。Agent 查询看不见源文件。
- `<slug>` 用 ASCII（从文件名来），中文标题放在 YAML 里，少踩 Windows 路径。
- 不建 `心理学/` 这种主题目录。
- 不建给人看的总目录页。编目是工具内存的，不是再让 Agent 读一份 `index.md` 全集。

一部书一个文件夹，是因为长文必须有「导读 + 可单独打开的一块」；笔记一文件一份，够短就不再套目录。

## 4. 一份资料头上有什么（给路由用）

每份 Markdown 文件头（书的 `导读.md`、笔记正文都一样）：

```yaml
title: 思考，快与慢
type: book          # book | note
tags: [心理学, 认知偏差]
description: 卡尼曼讲系统1/系统2与判断偏差。
source: 归档/....epub    # 有源文件就写；Agent 写的笔记可以没有
generated: false         # true = Agent 写的，方便以后清理
```

`description` 一句人话，是路由的主食（学 OKF：标题、标签、描述权重大，正文最后才打开）。

书的 `导读.md` 正文里再放**章节地图**（标题列表，不要章节全文）：

```
- 第1章 系统1与系统2
- 第2章 注意与努力
...
```

转换时能从 EPUB/PDF 的目录或一级标题生成就生成；生成不好就一张「尚未切章」的地图，查询仍能命中书名和描述。

## 5. 查询在工具内怎么走（真正省资源的地方）

Agent 只丢一句「心理学里和拖延有关的」进来。工具内固定四步，**每步都有硬顶**，不靠模型自觉。

| 内部步骤 | 打开什么 | 不做 |
|---|---|---|
| ① 编目 | 只读所有 `导读.md` / 笔记的 YAML（title/tags/description） | 不打开任何章正文 |
| ② 挑资料 | 打分取前 **3** 份（可配，硬顶 5） | 不按学科先赌一个文件夹 |
| ③ 看结构 | 只打开这 3 份的导读正文 / 标题列表 | 不打开整本书 |
| ④ 取片段 | 至多 **2** 个最相关章，每章只取命中标题附近一段，合计有 **字数硬顶**（建议约 2～3 千汉字） | 不切向量、不 top-k 碎片拼盘 |

打分学 OKF 的权重逻辑，不抄它的英文分词：标题 > 标签 > description > 章节标题 > 正文。中文先做子串/字面命中；词对不上以后再考虑只在①②上加向量，不改这套步骤。

**省在哪**

- 外面 1 次调用，不 4 次 MCP 往返（省延迟，这是 RAG 爽的那一点）。
- 里面几乎只读很短的 YAML 和导读；正文只碰赢家（省 token、省 IO）。
- 返回有字数硬顶，比「把相似段落全塞进上下文」省，也比 Agent 自己把整章 `read` 进来省。
- 不做向量索引、不按学科分库、不预切成几百个向量块。

和旧稿 L0–L5 的关系：那是给人看的层名，**作废**。上面四步只存在于代码，不暴露给 Agent。

## 6. 查询返回什么（相关内容，但不是 RAG）

返回一包结构化结果，不是散文、不是无身份的摘录：

- 命中了哪几份（title、身份、tags）
- 为什么像（命中了标题/标签/哪一章——给 Agent 否决用）
- **有限的相关正文**（④ 取出的片段）
- 若要更多：每条带身份，可再调 `阅读`

这和 mcpvault「搜索直接带 excerpt」不同：片段是 **先选对书、再选对章之后** 才切的，且有总字数顶。身份始终在，后面能覆盖、能清理。

`阅读(身份[, 范围])`：只在 Agent 明确还要更多时用。工具内仍限一次读的大小，禁止一次把整本灌出。

---

## 7. 和写入、待入库怎么接

- 待入库里的书/PDF → 转换 → `库/书/<slug>/`，YAML + 导读 + 尽量按一级标题分章；源文件进归档。
- Agent `写入` → 只能进 `库/笔记/`，必须是 Markdown + 同样的 YAML 头。不能冒充一次「我写了一本书」进 `库/书/`（书只从源文件转换来）。
- 查询同时打 `库/书` 和 `库/笔记`，用 `type` 区分，不让外面选库。

写入细则、新替旧策略仍未定，不塞进本草案。

---

## 8. 刻意不做

- 按学科分文件夹 / 多个向量库再智能路由
- 把渐进披露交给 Agent 自己逛
- 查询一次返回全书或无限摘录
- 预置主题词表
- 网页形态（需要时再加 `库/网页/`，头一样）
- 对外暴露 L0、L1 这种层名

## 9. 从对照项目里拿了什么

| 点 | 来自 | 我们的用法 |
|---|---|---|
| 标题/标签/描述权重大，search 不先给正文 | OKF `search.go`、CONVENTION §16 | 变成工具内①②③，外面甚至不必调第二次 |
| 搜索去正文、文件是正本 | basic-memory compact | YAML+Markdown 正本；返回里身份不丢 |
| 大纲再读一段 | mcpvault outline / lines | 放进步骤③④，不放进「搜索结果默认带摘录」 |
| 少工具、硬顶 | 参考笔记 §4.6、§5 | 对外几乎一扇查询门；条数和字数硬顶 |
| 不要人工切碎意思 | OKF §5.1 | 不切向量块；分章只按原书标题 |
| 学科分库 | 我们自己否掉的 RAG 路由 | 主题用标签 |
