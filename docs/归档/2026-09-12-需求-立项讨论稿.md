## 已锁定的产品方向

这是一间**常驻资料室**，给 Agent 用，不是给人翻的，也不是 RAG 聊天框。

人把这份 MCP / skill **标进这场对话**。标了之后：

- **检索**：Agent 自己去找。聊矛盾论，应能摸到《毛选》和旁边相关理论；聊一个具体心理问题，应能摸到相关位置。要不要继续往下读，由它自己定。
- **写回**：人要求写，它才写。不是把聊天自动倒进去。
- **人不用看库。**

它补的是 Agent 知识来源里缺的那一层：训练参数、临时联网搜索之外，**用户给的、可积累的专业材料**。任何支持 MCP 的 Agent 共用同一份。数据属于用户，永远是普通 Markdown，不属于某个工具、某一场对话。

三条来路进**同一个池子**：用户给文件、用户给网址、Agent 按要求写入的笔记/沉淀。换对话、换 Agent，资料还在。

以后 Agent 自己写下的东西，要能由智能体做清理和**新替旧**（同一主题只留一份有效的）。这一条方向锁定，做法未定。

### 形态：渐进式披露的文档库，不是向量库

知识以**一份份完整资料**存在（一本、一篇、一章、一条笔记），不切成向量块来存放。

检索是拟人的那一套：先定位「可能是哪几份、哪一章」，再决定要不要读原文。不是一问就把相似段落塞进上下文。

**不必先逛总目录。** 一句话就能找。第一次返回的是路标，不是正文。

**渐进披露的规则由代码执行，不靠模型自觉。**  
工具本身不把全文或一堆摘录泼回去；「找」和「读」分开。模型没有机会即兴改成 RAG。

默认不做向量检索。将来若经常「意思对、词不对、找不到」，只作为「找路标」背后的加速器，不改这间室的形态，也不改 Agent 看到的那两个动作。

### 明确不做

- 不以切块 + 向量当作库
- 不按领域拆成多个向量库再做智能路由
- 不替代模型常识，也不替代联网；库里有的以库为准，没有的照常聊或去搜
- 没被问到来源，不要表演「根据《某某》第 n 章」
