# 本轮 Spec：3.3 入库产品化（厚地图工作单 + 笔记冲突段 + Skill 合规）

> 日期：2026-09-19  
> 上级：`需求.md`  
> 产品代：`3.3.0`  
> 分支：`feat/v3.3-productize`（从 `feat/v3.2-precision` / `3.2.2` 开）  
> **禁止**入库调模型编俗称别名。禁止工具联网求证。禁止新开第七扇门。禁止为单书/单题写过滤器。

## 要解决什么

Agent 用 MCP 入库新书，产物对不齐现库 7 本。3.2.2 骨架能过 `map_problems`，「编地图」工作单被吃掉；7 本的读者问法、俗称别名、邻书边界是 Agent 手编的。笔记门能写，但 create 不覆盖、无笔记地图、写完不失效索引。knowledge Skill 正文可用，仓库手续没做。

本轮把入库做成「工具编排、Agent 动手」，入完状态对齐现库 7 本；笔记入库强制求证、建短地图、冲突段默认新覆盖旧。

## 不改

切块、导读结构、检索主路径、RRF/FTS 权重、冻结题集、六扇门数量、书正文。已有厚地图（7 本）不回写成骨架。`map_problems` **不**改为强制别名（结构校验保持；「薄」另判）。

## 1. 书入库：骨架仍写，薄不算入完

现库 7 本地图六段：`能解决什么 / 不解决什么 / 建议从哪读 / 依据块 / 章名 / 别名`。骨架必须也是这六段。

### 代码

1. `write_skeleton_map` 追加空的 `## 别名` 段（可以 0 条）。其它五段维持 3.2.2。
2. 新函数 `map_thin(book_dir) -> list[str]`（放 `index.py`，与 `map_problems` 并列）：
   - 活别名（`aliases` 去空白）**< 3** → `"别名不足"`
   - `能解决什么` 非空，且**每一条**都等于某章名、或是某章名前 40 字、或某章名以它为前缀 → `"能解决什么仍是章名"`
   - 缺地图交给 `map_problems`，本函数不重复报「缺地图」
3. `ingest_sources`：`map_problems` 或 `map_thin` 非空 → 该书 **未入完**；**永远**附 `_map_work_order`（不再只在 `not map_ok` 时）。
4. `_map_work_order` 写明对照现库的加厚要求：
   - 「能解决什么」改成读者问法（3–8 条，≤40 字），不是章名
   - 「不解决什么」保留 PyTorch 负样本，再加 1–4 条库里**其它书**才有的问法
   - 「建议从哪读」可与依据块解耦，点真正该先读的块
   - 「依据块」每条问法 → 活身份
   - 「章名」已机械补，别删
   - 「别名」至少 3 条：`<专名 ≥2 字> → 书/<slug>/<已存在块名>`，禁止公共词表
   - 走 `kb_lint_notes(action=apply)`，`op=update`，`target=书/<slug>/地图`
5. `kb_lint_notes scan`：`map_thin` 非空的书标 `未入完 骨架未加厚`（与缺地图、机械体检并列）。
6. 加厚写回后 `map_problems` 仍校验；不过则回滚（现逻辑）。`map_thin` 变空才从「骨架未加厚」消失。

### 仍是 Agent 干的

别名内容、读者问法、邻书「不解决什么」、建议块取舍。代码只给清单、校验、交还。

## 2. 笔记入库：求证 + 短地图 + 冲突段覆盖

不新开门。仍是 `kb_write_note`：`preview` → `verify` → `create`/`update`。真假由 Agent 认；工具不联网。

### 预览

除现有路标外，列出 **冲突段候选**：其它笔记里，与本稿同名的二级/三级标题（规范化后相同）。无候选则不写这一栏。

标题规范化：去首尾空白，去掉 `《》「」"'：:、．.`。

### 求证

四选一不变。`相符`/`部分不符` 的「已读」匹配改用**基身份**：`书/<slug>/<章>#n`、`#1`、`@偏移` 都算读过 `书/<slug>/<章>`。`#1` 与不带 `#` 等价（需求 4.1 已写，日志侧补上）。

### 短地图（同一文件，不新建目录）

写入时若正文没有 `## 能解决什么`，工具在文末补骨架：

```
## 能解决什么
- <YAML title 或前几个二级标题，3 条以内，≤40 字>

## 别名

## 依据块
- <能解决什么第 1 条> → 笔记/<slug>
```

不套书的六段（无「章名」「不解决什么」强制）。Agent 可加厚别名。笔记进索引仍是整份 raw（含这些段），**不改** FTS 列权重。

### 冲突段覆盖（默认新赢）

写入成功后，代码扫 `资料/笔记/` 里**其它**笔记：

| 条件 | 动作 |
|---|---|
| 双方都有二级/三级标题，规范化后同名 | 旧笔记该节正文换成新笔记该节正文；节下第一行加 `> 已被 笔记/<新slug> 覆盖` |
| 双方都无二级/三级标题，且 YAML `title` 规范化后相同 | **不新开第二条**：改为 update 已有那条（整篇覆盖）。`create` 撞同题无标题旧条时走这条，不 `uniquify` |
| 只是检索相似、标题不同 | 不改旧笔记 |

不改书。覆盖后 `invalidate()`。

### 索引

`create` / `update` 写盘后必须 `invalidate()`（现状只在 lint 里调，同进程搜不到新笔记）。
