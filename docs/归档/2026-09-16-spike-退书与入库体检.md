> 日期：2026-09-16  
> 性质：只读调研。不是 Spec。  
> 选题：`docs/问题.md` 的「退书」+ 类 A/B/C 的**可机械判定**部分  
> 上级：`需求.md`

## 0. 这一轮到底在问什么

`docs/问题.md` 里同时堆了三类事：

1. **准/全/省还别扭**（短问句、公共词、回忆录缠在一起）——检索打分维。
2. **类 A/B/C**（多册无标题树、字形坏、无文字层）——入库质量。
3. **退书门缺了**——六扇门没有「把已经入库的书拿掉」。徐景贤那本是人让主控直接删文件夹。

人点名：这一轮要**解决一些**，尤其是 **Agent 能按规则删除**；允许从根上重构看，不要默认小修。

本 Spike 只回答三个判断题：

- 这些问题是检索没调好，还是门的设计缺了一块？
- 退书该新开第七扇门，还是挂在现有门上？
- 这一轮该做多大？类 A 的「认册/卷再切」要不要绑进来？

---

## 1. 根因（不是单题）

### 1.1 设计缺口：入库是只进不出

六扇门是 ingest / query / lint 的卡帕西形状，但抄漏了「注销」：

| 对象 | 进 | 改正文 | 删 |
|---|---|---|---|
| 笔记 | `kb_write_note` | lint `update`/`merge` | lint `delete`（先清单后动手） |
| 地图 | 入库后补 / lint `update` | 可以 | 不能删文件，只能 `stale` |
| **书** | 收件箱 / 指定入库 | **焊死不许** | **没有门** |

`需求.md` 2.1.3 原文：「书是原文，进库后不改、不净化。笔记更自由，可以改、合并、删。」

这句话的本意是 **不重写书正文**（lint 的 `test_apply_chapter_still_rejected` 钉的就是这个）。它被执行成了 **整本也不能走**。人要退一本扫描图，只能绕过工具去删文件夹——和 `docs/功能流程.md`「正路都经 Agent 调工具」直接打架。

这不是小修补能补上的：缺的是**能力**，不是某条正则。

### 1.2 设计缺口：入完几乎只看地图

`ingest.convert_one` 转完就落盘、源文件进归档、`invalidate()`。所谓「不算入完」今天只有一件事：`map_problems` 报缺地图。图文比、超长块、乱码文件名、册层级丢失，**全部照样进检索**。

类 A/B/C 的书一旦进来，检索层只能用闸门把它们「藏起来」。第 6–7 轮已经把 Q 组准打到 13/13；N 组剩下的「回忆录缠在一起」，一部分是公共词，一部分是**坏书/结构烂的书仍占 5 格**。继续给检索打补丁，是在给写死的入口做善后。

### 1.3 类问题分别怎么形成的

| 类 | 形成机制 | 是不是设计失误 | 小修够不够 |
|---|---|---|---|
| **退书** | 门集合不对称 | 是。ingest 没有反操作 | 不够。必须开门 |
| **C 无文字层** | 转换产物几乎全是图，仍当书 | 是。体检只查地图 | 入库拒绝 + 已入的能退。不 OCR（产品已定） |
| **A 多册无标题树** | 无 ATX 时 `STRUCT_RE` 认「章/篇/一、」，**不认册/卷当上级**；`slugify` 剥光中文，文件名「资本论(1-3)(套装共3册)」变成 `1-3-3` | 切块策略偏了（结构只该命名，但命名也丢了层级） | **认册/卷再切**才治本；本轮先能**标未入完 + 能退 + 能重入**。不绑在这一轮切块里 |
| **B 字形/切点过碎** | 书名走了第一个「第一章」；无 ATX 时「一、」撕篇；字体映射 癿/丌 | 书名优先级已写在需求，实现没挡住「第一章」当书名；字形是转换器的锅 | 书名规则可小修；字形映射另开；本轮只**标**乱码文件名，不重写四十万字 |
| **D 公共词撑满** | 已落地第 6–7 轮 | 当时库太小把问题藏住了 | 已做。剩下的 N 组短问句**先让坏书能离开再量**，不要本轮再拧闸 |

`slugify`（`ingest.py`）`[^a-zA-Z0-9]+` 剥中文是 ASCII slug 这条需求的字面执行，加上中文文件名只剩套装编号，就得到 `1-3-3`、`1-7`。需求写「slug 用 ASCII」，没写「只剩数字也行」。空心 slug 是执行过严，不是检索问题。

### 1.4 所以：重构还是打补丁？

**退书 + 入库体检：改门，不是打补丁。**  
**检索公共词：本轮不做。** 没退出通道之前，准度补丁分不清「闸不好」还是「不该在库里的书还在」。  
**认册/卷再切：下一轮。** 没有退书就没法从归档重入；有退书之后，资本论这种「有用但切烂」的书才走得了「退 → 重切 → 再入」。

## 2. 现状（代码，只读）

对外仍是 7 个函数、口头 6 扇门：`kb_search` / `kb_read` / `kb_ingest_inbox` / `kb_ingest_files` / `kb_write_note` / `kb_lint_notes` / `kb_inspect`。

净化（`notes.py`）：

- `scan`：笔记短/重复/没抬头/过期/死链；地图缺、死链、早于重切。**不扫书的图文比、块长、文件名。**
- `apply`：笔记 `delete`/`update`/`merge`；地图 `update`/`stale`。`_touches_book` 为真 → **整单拒绝**。`书/<slug>` 和 `书/<slug>/章` 一样被拒。
- 笔记 `delete` **不** `invalidate()`。同进程里删了还能搜到。这是删除机制自己的洞。

入库（`ingest.py`）：

- `convert_one`：转 → 切 → 写块和导读 → **源文件搬到归档** → `invalidate`。不写地图。
- 切块：有 ATX 走 `_cut_level`（已能把 ATX 的「卷」并进其后第一块）；无 ATX 才 `is_structure_line`，正则没有「册/卷」当上级。
- 书名：`epub_title` > 第一个非版权标题 > 文件名。PDF《文革史》没有 dc:title，第一个标题是「第一章 现代民族国家」——需求优先级第三条被「看起来像标题的第一章」抢走。

## 3. 别人怎么删（可照搬 / 不要抄）

| 来源 | 怎么做 | 可照搬 | 不要抄 |
|---|---|---|---|
| [Karpathy LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) | 三层：raw 不可变；wiki 由 LLM 维护；**lint 是体检**（矛盾、过期、孤儿），不是后台自动删 | raw 不动；lint 先看后动手 | 他们编译 wiki 代替原文；我们书正文是正本 |
| 本机 `lint` skill（96_llm-wiki） | 只读扫描；修复前等人确认；**raw 不动**；删/废弃先列影响面 | 先清单；源文件不删 | 双链/orphan 那套 wiki 账本 |
| [basic-memory `delete_note`](https://github.com/basicmachines-co/basic-memory/blob/main/src/basic_memory/mcp/tools/delete_note.py) | 一锤子硬删，`destructiveHint: true`；找不到返回 False | 失败要说清楚身份怎么写 | **不要一锤子**。我们净化已经是 scan/apply，比他们安全 |
| mcpvault | 破坏性写要 `confirmPath` | 路径必须对得上身份 | 搜索带摘录（反例） |
| [Safe file-write: preview/confirm/apply](https://startdebugging.net/2026/08/safe-file-write-tools-for-an-agent-preview-confirm-apply/) | MCP elicitation + 签名 requestState，防「预览 A 执行 B」 | **预览和执行必须绑同一份清单** | 不上 2026-07-28 elicitation；本库 stdio FastMCP 用现成 scan/apply 就够 |
| second-brain-skill `/wiki wipe` | 回收站，可恢复 | 「退不等于毁源」 | 不另建回收站目录。归档里的源文件就是可重入的副本 |
| Paperless-ngx | 删文档后索引跟着走 | **删正本必须失效索引** | 他们是文档管理系统，不是资料室 |

**没有**一个现成 PyPI 包能当「退书门」。该自建，而且该长在已经存在的 scan/apply 上，不要新开一排工具。

## 4. 三条路

### 甲 · 净化扩成「库卫生」（推荐）

`kb_lint_notes` 仍是那一扇门。`scan` 加书的机械体检；`apply` 新 op `withdraw`，身份只能是整本 `书/<slug>`。章、笔记、归档、原始资料都动不了。

- 不新开第七扇门（`docs/计划.md` 写过不做这个）。
- Agent 已经会「先 scan 再 apply」。
- 「书不改」继续焊在「不准改/删某一章」；退的是整本身份。

### 乙 · 新工具 `kb_withdraw`

入库的反操作，语义干净。坏处：工具 +1；体检仍要有人扫，最后还是两扇门干一件卫生的事；和「工具要少」打架。

### 丙 · 继续人手删文件夹

现状。Agent 按规则退不了。人已经做过一次，正路不该是这个。

**选甲。** 乙的「反操作」语义用 `op=withdraw` 表达，不必新函数。

## 5. 本轮边界（探路结论）

做：

1. 退整本（先清单后动手，代码焊身份和范围）。
2. 入库/扫描能**机械**标：无文字层、超长块、空心 slug、同名章撞车、乱码文件名、缺地图（已有）。
3. **新**的无文字层源文件拒绝入完，源文件留在 `原始资料/`，不落书、不归档。
4. 新入库空心 slug（剥完只剩数字和横线）改走 `book-{hash8}`。
5. 任何删除（笔记或书）后 `invalidate()`。

不做（留给以后，有退书才能做）：

- 切块认「第 X 册/卷」当上级、重切资本论（类 A 治本）。
- 字形小映射表重写正文（类 B 治本；正本仍是转换结果）。
- 检索公共词再拧闸（问题清单第 1 条）。
- OCR、向量、索引落盘、第七扇门、回收站目录、按章删、删归档源文件。

真库这一轮**不退任何现有书**（合成库闸门钉行为）。三维打分当对照：应与第 7 轮同分；同分不是失败，说明没伤检索。
