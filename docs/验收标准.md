# 检索与入库的验收标准（冻结版）

> **冻结声明：** 下面的题集（Q1–Q10）和取词表（W1–W20）一旦定下就不许随手改。
> 要改必须写明理由并记在第八节。否则改完代码顺手改题，就成了自己给自己发奖状。
> 规格以 `需求.md` 为准，本文只管"怎么判定做没做好"。
> 建立：2026-09-13（含改造前基线）

---

## 零、这套测试要证明三件事

1. **不漏**——书里有的内容，Agent 一定检索得到。**入库必须配合检索**，不许出现"内容明明在书里，却谁也搜不到"。
2. **不多余**——路标里一个字的正文都没有；无关的书不许溜进路标；读多少取决于问题多大。
3. **正好结束**——窄问题读一块就够；宽问题才多读。**不鼓励"为了保险把整本读完"**。

## 二、每题记五个指标

1. **召回**：期望的每本书在不在路标里（按"本"计）。
2. **精准**：期望的块在不在建议块里？Top-1 还是 Top-3？
3. **不多余**（三条，全都要过）：
   - a. 路标里**一个字的正文都没有**（机械检查：正文埋一句独有的话，grep 路标输出，必须搜不到）
   - b. **无关书不得进路标**（见上表那一列）
   - c. Q6 必须返回"没有像的"
4. **可达**：照路标点名 → 拿到全文，且**不带"已截断"标记**。
5. **取用（正好结束）**：从路标出发，为了答对这个题，**实际点名读了几块**。
   - 窄题（最少 1 块，Q7/Q8/Q9）：实际 ≤ **2 块**
   - 其余题：实际 ≤ **最少 + 2 块**
   - 任何题都**不许**"把整本读完再挑"

## 三、取词回捞（W1–W20，冻结）——"入库配合检索"的机械证明

**原理**：从书里抽一个确实存在的词，拿去检索，**必须回捞到它所在的那本书**。
一个词回捞不到，就说明"内容在书里、Agent 却搜不到"——这正是要焊死的性质。

**这组和 Q1–Q10 的区别**：Q 组考"问得对不对"，W 组考"**覆盖全不全**"。Q 组只有 10 题，覆盖不了全书；W 组是把入库和检索焊在一起的那道闸。

## 四、入库"完美"标准（全库机械扫描，全过才算）

1. **每块 ≤ 4000 字**
2. **每块有名字，且名字来自书里**——不许 chapter / 空名 / 编造
3. **字数守恒**：全库块字数之和 ≥ 转换产物字数的 **99%**（防切块丢字）
4. 没有空块、没有只有标题没有正文的块
5. **确定性**：同一问题问两次路标一致；索引重建两次结果一致
6. 硬盘上**不出现索引文件**（索引只在进程内）

**第 3 条是入库的兜底闸**：切块算法再花哨，也不许把书里的字弄丢。配合第三节的取词回捞，一进一出两头卡住。

## 六、怎么跑（两层）

**第一层：pytest 机制闸门**（合成小书，随代码跑，快）
管机制：每块 ≤4K、不带正文、负样本、单字词、虚词降噪、索引不落盘、确定性、字数守恒、无标题书不崩。

**第二层：线上验收**（真库，跑一次，出对照表）
在真库上跑 Q1–Q10 + W1–W20，逐条对照本文表格填"实测"列，和第七节基线比。
真库的 `资料/` 是本地私产、不上 git，所以这层不进 pytest。

## 八、冻结规则

1. 题集、取词表、通过线**不许因为"实现起来麻烦"而放宽**。
2. 要加题、换词、改线，**写理由**记在这里，并注明日期。
3. 每条题和每个词都**先写死期望**，跑完再对照——不许跑完看着结果改期望。
4. 基线那一节**不许覆盖**，每次验收另开一节追加。
