## 零、这套测试要证明三件事

1. **不漏**——书里有的内容，Agent 一定检索得到。**入库必须配合检索**，不许出现"内容明明在书里，却谁也搜不到"。
2. **不多余**——路标里一个字的正文都没有；无关的书不许溜进路标；读多少取决于问题多大。
3. **正好结束**——窄问题读一块就够；宽问题才多读。**不鼓励"为了保险把整本读完"**。

## 二、每题记的指标（工具项 vs 剧本项）

1. **召回**：期望的每本书在不在路标里（按"本"计）。
2. **精准**：期望的块在不在建议块里？Top-1 还是 Top-3？
3. **不多余**（三条，全都要过）：
   - a. 路标里**一个字的正文都没有**（机械检查：正文埋一句独有的话，grep 路标输出，必须搜不到）
   - b. **无关书不得进路标**（按第一节「无关书口径」：非期望即无关，不点名某一本）
   - c. Q6 必须返回"没有像的"

线上收成三维（准 / 全 / 省）见第九节。召回→全，不多余→准，占用与取用→省。精准 Top-k 仍可记在摘记里，不进三维。
4. **可达**（工具）：照路标点名 → 拿到该窗全文，且**不带"已截断"标记**。超长篇点 `#2` 必须能拿到下一窗，而不是再从文件头开始。
5. **取用 / 轮次 / 不重复读**（**Agent 剧本，不挡代码合并**）：工具只保证路标有命中块数和邻块行，不许为过线去限轮次或喊停。窄题（Q7/Q8/Q9/Q11）剧本目标 ≤4 块 ≤2 轮（Q11 最少 1 块）；其余 ≤最少+2；Q12 ≥3 块覆盖三篇 ≤3 轮；同一身份不读第二遍；不许整本读完再挑。

## 三、取词回捞（W1–W20，冻结）——"入库配合检索"的机械证明

**原理**：从书里抽一个确实存在的词，拿去检索，**必须回捞到它所在的那本书**。
一个词回捞不到，就说明"内容在书里、Agent 却搜不到"——这正是要焊死的性质。

**这组和 Q 组的区别**：Q 组考"问得对不对"，W 组考"**覆盖全不全**"。W 组是把入库和检索焊在一起的那道闸。通过线是「命中集合含所在书」，不是 Top-1 独占（W12「合作」毛选出现更多）。

## 四、入库"完美"标准（全库机械扫描，全过才算）

1. **块 = 自然篇/章**：毛选应落到 `###` 篇名（实践论、矛盾论、各阶级各自一块）；不预切 4K 文件
2. **每块有名字，且名字来自书里**——不许 chapter / 空名 / 编造 / 带着 `[\\*](#id0a)`
3. **字数守恒**：切块后各块正文（去 YAML）字数之和 ≥ **切块前 markitdown Markdown** 的 **99%**。对照物是转换产物，不是 epub
4. 没有空块、没有只有标题没有正文的块
5. **确定性**：同一问题问两次路标一致；索引重建两次结果一致（属检索，附在这里一起扫）
6. 硬盘上**不出现索引文件**（索引只在进程内）

**第 3 条是入库的兜底闸**：切块算法再花哨，也不许把书里的字弄丢。配合第三节的取词回捞，一进一出两头卡住。

**第三层：线上剧本**（真 Agent）

## 九、三维打分（每轮改代码后必记）

给人看进步还是退步。三个数**并排**，**不合成总分**。优化了 A 伤了 B 必须看得见。

红线（第五节：无正文、Q6 空、无关书、可达、W 回捞、入库 6 条）仍然各自必须 100%。三维是同一批题的对照卡，**不是**用平均分盖掉红线。红线失守的题号必须在汇总里点名。

### 9.1 三维（人话）

| 维 | 人问的是 | 怎么判 | 聚合 |
|---|---|---|---|
| **准** | Agent 找到的是不是该找的 | 有闲书（非期望）→ 0；该有期望却一个都没有（空或全错）→ 0；否则 1。Q6 相反：空才 1 | 过 / 应测 |
| **全** | 复杂题的多个来源都找到了吗 | 命中的期望单位 / 该题期望单位（本或篇，见 9.2） | Σ命中 / Σ期望 |
| **省** | 够了是否停下、有没有撑爆上下文 | 路标字超线或路标含正文 → 0。若跑了剧本，读块/读总字/轮次超线也 0 | 过 / 应测 |

质量目标（召回允许漏 1、Top-3 ≥90%、Top-1 ≥70%）仍有效。漏 1 本时：**全**按分数记（例如 2/3），不要把整题打成过；**准**仍按有没有闲书打。

不测的维留空，不打 0 也不打满分。Q8 只在 pytest 临时库，不进线上分母。W1–W16 只进「全」，每轮必须全跑。

「全」应测单位合计：2+2+2+2+3+2+3+16 = **32**。  
「准」应测：Q1–Q7、Q9–Q14 共 **13** 题。  
「省」应测：Q1–Q5、Q7、Q9–Q14 共 **12** 题。

### 9.3 省的细则

机械层（每轮必跑）：

- 路标含正文 = 0（红线，破则该题省=0 且红线点名）
- 路标字数：窄/概要（Q7/Q9/Q11/Q13/Q14）≤1500；宽（其余应测省的题）≤2000
- 热 `search_ms` ≤2000（超了记在汇总，不单独一维；反复超再开问题类）

剧本层（Q9–Q14 建议跑；没跑就注明「剧本未跑」，省只按机械层打）：

- 读块、读总字、轮次：沿用第二节第 5 条和第六节占用目标（窄/概要读 ≤2 块、读总字 ≤9000、轮次 ≤2；宽题读 ≤最少+2、读总字 ≤24000、轮次 ≤3；Q14 不许通读五夜）
- 剧本超标 → 该题省=0

没记路标字数，该题省标 **未测**，不得当成过。一轮里省未测超过 3 题，这轮「省」整维作废，汇总写「省：未测」，不许填假分。

### 9.4 半过怎么拆

禁止给整题打 0.5。

- 期望在、闲书也在 → 全给分、准=0
- 空路标或期望一个都没有（且不是 Q6）→ 准=0；若该题测全，全=0
- Q6：空 → 准=1；任何非空 → 准=0

### 9.5 一轮必须写下的东西

写**两处**，都进 git，只追加：

- **明细** → `检修/验收记录.md`（第 5 轮起用该文件顶部模板）
- **流水一节** → `检修/打分记录.md` 文末（准/全/省、书本数、块数、pytest、红线、对照、**本轮代码短哈希**）

打开 `检修/打分记录.md` 往下读就是分数怎么变的，不必翻 git。git 只防丢失。`检修/calls.jsonl` 不进 git，不能当账本。

1. 日期、轮次名、触发（哪个 Spec / 哪次改 `mcp/`）
2. **书本数、块数**：书本数 = `资料/书/` 下目录数；块数 = 这些目录里除 `地图.md` 外的 `.md` 数（含导读）。没有这两项，对照作废
3. pytest 全绿的 passed 数（机制闸门，不进三维）
4. 题表：每题 准、全(命中/期望)、省、路标字、search_ms、读块、读总字、轮次、三栏条数、一句话判定
5. 汇总三行：`准 a/13`、`全 x/32`、`省 b/12`，差/漏/超的题号列出来
6. 对照上一轮有数据的同维：升 / 降 / 平。上一轮该维未测 → 写「无对照」
7. `检修/打分记录.md` 文末追加一节，代码能对上那一轮实现

W 组 16 词必须出现在题表或另表，不许只抽 5 个词。

压力题（N 系列、新书探针）可以附录，**不进三维分母**，除非先写入本节变更记录、冻结期望。

### 9.6 什么时候必须打这一轮分

凡改了 `mcp/` 且触及 **检索、索引、入库切块、路标格式、阅读窗、地图生成**，本轮 Spec 归档之前必须做完 9.5。没有验收记录新节、**没有打分流水新节**，**不许说做完**，不许删 `docs/本轮Spec.md`。

只改写笔记步骤、净化、自检文案：pytest 对应闸门即可，不强制线上三维。但一旦顺手改了 retrieve / index / ingest，仍走全套。

Spike（只读）不打分。
