# 借鉴与开源

> 服务于 `需求.md`；架构见 `docs/重构架构.md`。第三栏规格叫「仅语义」（章向量），地图是字面结构字段，不是单独一栏。
> 本文只回答一件事：**哪些直接拿来用、哪些只抄思路、哪些明确不用**。不写项目百科。
> 核实日期 2026-09-16。事实分两级：**本机实测**（venv / 代码行号）与**联网核查**（带 URL）；查不到的照写「查不到」。

## 0. 原则

分三档，判据只有一条：**这东西进来以后，谁说了算。**

- **直接用**（§1）：现成库或模型，在我们自己的 Python 里 `import` / 调用，**不 fork 成产品**。要用就直接依赖，不自己重写。
- **只借鉴**（§2）：抄流程、抄字段、抄权重设计；代码自己写，或就是十几行算术。
- **明确不用**（§3）：不当整包产品、不当正本、不当依赖。

三条红线，任何一档都不许破：**书进库后不改正文**；**检索只回身份和理由、永不回正文**；**正本永远是 Markdown，索引是可扔的派生物**。

需求代号（下同）：`R1` 本机资料室 MCP｜`R2` 正本 Markdown、书不改｜`R3` 只回身份、阅读另点名+字数顶｜`R4` 一句问话要准（字面 + 语义两路，三栏合流）｜`R5` 跨多本一次点齐｜`R6` 少占上下文｜`R7` 六扇门｜`R8` 中文长书、自然篇为块｜`R9` 不重复造轮子：检索算法用现成，资料室合同自己留。

## 2. 只借鉴思路

| 来源 | 抄什么 | 不抄什么 | 落在本库哪一层 |
|---|---|---|---|
| **tobi/qmd**（[repo](https://github.com/tobi/qmd)，MIT，Node/TS） | ①**扩写分流**：改写按类型只进对应的路（原话 "Typed expansions are routed exclusively: `lex`→BM25/FTS, `vec` and `hyde`→vector search"），不是所有改写喂所有路；②**RRF 融合** `score = Σ(1/(k+rank+1))`、**k=60**，原查询加权 ×2、头名另有加成；③**query / get 分工**：身份与正文是两个工具（`query`/`search` 只回 `qmd://` 身份，`get`/`multi_get` 才取正文），与本库同构；④**上下文注解**（它叫 Context System）：把一段注解挂在路径上、子文档**继承**，帮 Agent 看懂「这份东西是干什么的」 | 不抄 **Node + node-llama-cpp + GGUF**（三个本地模型：embeddinggemma-300M、qwen3-reranker-0.6B、qmd-query-expansion-1.7B）；不抄**索引落盘** `~/.cache/qmd/index.sqlite`（FTS5 + sqlite-vec 都落盘）；不抄**结果带 snippet**——那正是本库明令禁止的「搜索带正文摘录」；不抄它的权重数值（×2 / +0.05 是它的调参，本库候选池只 5 格，重排无东西可排） | 融合层 + 查询侧（`retrieve.py`）；上下文注解对应**导读 / 地图**那一层，不是正文层 |

## 3. 明确不用

| 项目 | 为什么 | 若只偷一句 |
|---|---|---|
| **tobi/qmd**（[repo](https://github.com/tobi/qmd)） | 是**整包本地检索引擎**：Node + node-llama-cpp + GGUF、索引落盘 `~/.cache/qmd/index.sqlite`、结果带 snippet。装进来等于换掉检索层与部署形态，六扇门、白盒闸门、验收题集全部要重写 | 「**仅字面那一路完全可以不落盘**；要落盘的只有可作为缓存丢弃的那部分」——以及纯 RRF 会稀释精确命中（"Pure RRF can dilute exact matches when expanded queries don't match."），所以原查询要加权 |
| **basic-memory**（[repo](https://github.com/basicmachines-co/basic-memory)） | **AGPL-3.0**（改了当自己产品分发不行），要 Python ≥3.12（本机 3.11.4）；更硬的是它**回正文摘录**（"Matched chunk text is included so the LLM gets context"），与本库「永不回正文」正面相反 | 「**文件是正本，库是派生的**」；以及搜索结果**故意去掉正文**这件事（它的 `_compact_search_response` 注释：*Keep discovery identities and pagination without repeating source prose*） |
| **RAGFlow / kotaemon / AnythingLLM**（[RAGFlow](https://github.com/infiniflow/ragflow) Apache-2.0、[kotaemon](https://github.com/Cinnamon/kotaemon) Apache-2.0、[AnythingLLM](https://github.com/Mintplex-Labs/anything-llm) MIT） | **不是因为许可证**——是它们都是**整套 RAG 应用**：文档→切块→向量库（默认 ES / LanceDB），回的是 chunk 片段 + 引用；产品形态不同类，装进来等于换产品 | RAGFlow 的「切片**可控可解释**、可人工调整」这个意识——我们的块名必须来自书里、切完字数守恒 ≥99% |

## 4. 和「不重复造轮子」的关系

造的是**资料室合同**，不造 BM25 和嵌入。

**不造的**：BM25 与字面切分（标准库 FTS5 自带 `bm25()` 与列权重参数）；PDF/EPUB 解析（markitdown）；嵌入模型与推理（BGE-M3 + FlagEmbedding，或 ONNX 路线配已在 venv 的 onnxruntime）；向量近邻（真需要时 sqlite-vec，或直接拿已装的 numpy 暴力扫）。

**自己留的，一样都不能外包**：**身份**（`书/<slug>/<章>`、`笔记/<slug>`，`index.py:389/431` 生成，谁也不许改名）；**索引面与**7 列结构（正文/块名/书名/别名/地图各占哪一列）；**窗**（`retrieve.py:33` 单块 8000 字、`:35` 整次 24000 字、一次最多 5 块、显式 `#n`、不引隐藏游标）；**只回身份不回正文**（连 FTS5 无内容表都在替这条看门）；**三栏路标**（两路都中 / 仅字面 / 仅语义；地图进字面结构列）；**退书与净化**（整本可 withdraw，篇/章不动）；**求证闸门**（`相符` / `部分不符` 必须先真读过）；**卡壳交还**（不拆闸门抄近路）。

理由一句话：上面那些算法件，任何一个成熟库都比我们写得好；而上面那些合同条目，**没有一个开源项目会替我们守**——它们各有各的产品观（回摘录、编译完不回原文、图当正本），照抄哪一条都会先把本库最硬的三条红线拆掉。
