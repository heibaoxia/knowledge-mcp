# 写笔记时怎么求证（给 Agent）

> 规格以仓库根目录 `需求.md` 4.4 为准。本文只说**怎么做**，不能代替闸门。
> 跳过预览或求证，工具会拒绝写入。

写笔记是同一扇门的三步：`preview` → `verify` → `create` / `update`。

## 先分清这是哪类稿

| 你要留下的 | 求证结论 | 要不要先读库 |
|---|---|---|
| 感悟、判断、打算、情绪 | `非事实` | 不必 |
| 书里有、你核对过 | `相符` 或 `部分不符` | 必须先 `kb_read` 依据 |
| 像事实，但库里没有 | `库中无` | 不必装查过 |

对不上书，标 `部分不符`，**不许改书**。

## 步骤

1. 写成 Markdown，抬头有标题和几句介绍。
2. `action=preview`。看类似条目：该改旧的就改，不该开两份一样的。
3. 若是 `相符` / `部分不符`：用检索路标上的建议块，一次 `kb_read` 把依据取走（可多块），再填 `sources`。
4. `action=verify`，稿上带：
   - `verify:` 四选一
   - `sources:` 身份列表（`书/<slug>/<章>` 或 `笔记/<slug>`）；`非事实` / `库中无` 可空
5. 同一份正文再 `create` 或 `update`。改了正文必须从预览重走。

## 不许做的

- 没读过就写「根据《某某》第 n 章」或填 `相符`
- 来源写成书名而不是身份，或一次要整本
- 把求证结论写进 skill 就算过关——工具要看日志里是否真的读过
- 为求证新调一个不存在的 MCP 工具
- 库是空的还假装查过；没有就 `库中无` 或去联网，并告诉人

## 抬头样子

```yaml
title: 拖延不是时间问题
type: 笔记
intro: 对照《拖延心理学》第一章后的笔记。
verify: 相符
sources:
  - 书/delay/第一章 为什么拖
generated: true
```

感悟把 `verify` 写成 `非事实`，`sources` 可省略。
