# 这个工具怎么干活（给人看的说明书）

> 现行规格是仓库根目录 `需求.md`。本文是同一套规则的白话步骤版。
> 写法尽量白话。
>
> 三个角色：
> - **人**：你。往规定文件夹丢文件、对 Agent 说话。
> - **Agent**：外面那个助手。真正去读、判断、写字、找书。
> - **代码**：本工具。不管理解内容，只管 **步骤走不走得过、手伸不伸得出去**。

一句话：人点名用这个库；Agent 来干活；代码规定它必须走哪些步、每一步只能拿到什么。

---

## 东西放哪

人碰的（工具检索时当没看见）：

- `原始资料/`：只准往这儿丢 PDF、EPUB、MOBI
- `原始资料归档/`：转成 Markdown 之后，源文件搬到这儿，不再动

工具检索只看：

- `资料/书/`：正式的书、长文。一部书一个文件夹，门口一份很短的「导读」（标题、几句话是干什么的、有哪些章）。进库以后当原文，**不改、不净化**。
- `资料/笔记/`：心得、感悟、非书的东西。一份一个 Markdown。可以改、可以合并、可以删。

主题（心理学、矛盾论）不建文件夹，写在每份材料抬头那几句里。找的时候书和笔记一起找，不用跟工具说「去翻笔记」还是「去翻书」。

---

## 一共几扇门

Agent 能调的就这些（都要它来点，工具自己不会在后台偷跑）：

1. **检索** — 想了解什么，到库里去找
2. **收件箱入库** — 把已经丢在 `原始资料/` 里的，全部转成书
3. **指定入库** — 只把点名的那几个源文件转成书
4. **写笔记** — 把非书的文字写进笔记
5. **净化笔记** — 整理笔记（合并、更新、丢掉过期的），动不了书
6. **自检** — 看最近怎么被用、卡在哪；给建议；要改功能先写提案

下面每个功能：先说谁来用，再从输入走到输出，每一步标好谁干。

---

## 功能 1：检索

**谁用：** 你让 Agent 用这个库去谈一件事的时候。  
**外面不管：** 它为什么问、问完怎么跟你聊。  
**工具不管：** 书从哪买的、你选过哪本。

### 场景 A：你说「用这个库，给我讲讲拖延」

1. 你让 Agent 用这个工具，并说出想了解什么。**【人】**
2. Agent 调用「检索」，把那句话交进来。**【Agent】**
3. 工具只在 `资料/` 里扫所有材料的**抬头**（书名/笔记名、几句介绍、标签、书的章节名），不打开正文。**【代码】**
4. 打分，只留下最像的几条（数量有死上限）。**【代码】**
5. 还回去的是**路标**：哪几份、凭什么像。默认**没有章节正文**。**【代码】**
6. Agent 自己判断：够不够用、要不要跟你提书名、要不要再看原文。**【Agent】**
7. 够用就拿路标去跟你聊。**【Agent】**（工具不再管）

### 场景 B：它觉得要再看某一段

接着上面第 6 步，它决定加深：

8. Agent 调用「阅读」，点名是哪一份、哪一章（必须是上面那种有身份的，不能说「把心理学全给我」）。**【Agent】**
9. 工具只打开那一块，字数有死上限，整本灌出来会被拒绝。**【代码】**
10. Agent 拿到这一段，自己决定怎么跟你说、提不提来源。**【Agent】**

### 场景 C：库里没有这事

1～5 同上，第 5 步是空的或很不像。**【代码】**  
6. Agent 如实告诉你：库里没有，别装查过。**【Agent】**

### 场景 D：书和笔记都会出现

你问「心理学」，库里既有一本教材，也有一条你以前的感悟。同一次检索里两条都可以作为路标出现，不用先选「搜书还是搜笔记」。**【代码 负责一起搜 / Agent 负责之后读哪条】**

**检索这一门，代码焊死的步：** 先抬头、后正文；正文必须点名；一次不能拿走太多。  
**Agent 干的：** 问什么、要不要加深、怎么跟人说。

---

## 功能 2：收件箱入库

**谁用：** 你已经把书丢进 `原始资料/`，让 Agent「把里面的收进库」。  
**不管：** 文件是谁下载的。工具只处理文件夹里已经有的。

### 场景 E：你丢了三本，让它入库

1. 你把 PDF/EPUB/MOBI 放进 `原始资料/`。**【人】**
2. 你对 Agent 说：把原始资料入库。**【人】**
3. Agent 调用「收件箱入库」（不用报书名）。**【Agent】**
4. 工具把这个文件夹里**所有**待处理的源文件，一本本转成 Markdown。**【代码】**
5. 转好的放进 `资料/书/`（一部书一个目录，门口写好导读抬头）。**【代码】**
6. 源文件从 `原始资料/` 搬到 `原始资料归档/`。**【代码】**
7. 告诉 Agent：成功几本、哪本失败了。**【代码】**
8. Agent 转述给你。**【Agent】**

转格式、搬家、写导读骨架，都是工具自己做。Agent 不许跳过转换、直接拿 PDF 去检索，也不许改归档里的源文件。

---

## 功能 3：指定入库

**谁用：** 你说「把 B、C 两本放进库」；文件可能还不在收件箱里。  
**和收件箱的差别：** 只收点名的文件，不把收件箱里其它东西一锅端。  
**工具仍然不找书。** 找不到是 Agent 的事。

### 场景 F：推荐了三本，你选 B、C

1. 你们聊天选出 B、C。**【人 + Agent】**（工具看不见这场聊天）
2. Agent 自己去找这两本的源文件。**【Agent】**
3. 找不到：告诉你，**不要**调用入库。**【Agent】**
4. 找到了：调用「指定入库」，交上文件路径（或已经丢进 `原始资料/` 的文件名）。**【Agent】**
5. 工具**只转这几个文件**，其它待处理的不动。**【代码】**
6. 和收件箱入库一样：Markdown 进 `资料/书/`，源文件进归档。**【代码】**
7. 回报成功/失败。**【代码】**
8. Agent 告诉你入库了。**【Agent】**  
   工具只知道「又进了两份合法的书」，不知道这是你选的 B、C。

指定的是**文件**，不是书名。对工具说「去弄一本《思考快与慢》」不算指定入库，那是找书，工具拒绝或根本没有这种叫法。

---

## 功能 4：写笔记

**谁用：** 非书的东西——你的感悟、讨论里要留下的话、Agent 整理的心得。更自由，但只能进笔记，不能冒充一本书。

### 场景 G：你说「把刚才那句记下来」

1. 你让记一条笔记。**【人】**
2. Agent 写成 Markdown，调用「写笔记」。**【Agent】**
3. **强制先搜：** 工具用同一套检索，在笔记（也可以提示书里已有的）里找像不像已有的，把类似的路标扔回去。**【代码】**  
   这一步跳不过：不搜就直接新建，不允许。
4. Agent 判断：是改旧的一条，还是确实该新开一条。**【Agent】**
5. Agent 再提交：更新某条，或确认新建。**【Agent】**
6. 工具检查：必须是 Markdown、只能进 `资料/笔记/`、动不了书、抬头得有标题和几句介绍（不然以后检索扫不到）。**【代码】**
7. 过了就写入；不过就拒绝并说明哪条规则没满足。**【代码】**
8. Agent 告诉你记好了或没记下。**【Agent】**

### 场景 H：它想把一本「假书」当书写进去

走写笔记却想写到 `资料/书/`，或指定入库却交来一段自己编的正文、没有源文件。**【代码 直接拒绝】**  
书只从源文件转换来。

---

## 功能 5：净化笔记

**谁用：** 你让整理笔记，或 Agent 觉得笔记该打扫了。  
**只打扫笔记。** 书、归档、原始资料一律不动。  
**不在后台自己跑**，每次都要 Agent 来点一下。

### 场景 I：你说「把笔记整理一下」

1. 你让整理，或 Agent 决定该净化了。**【人 或 Agent】**
2. Agent 调用「净化：先扫描」。**【Agent】**
3. 工具只扫 `资料/笔记/`，列出可疑项，例如：标题很像的好几条、太短、没抬头、已经标过期、明显重复。**【代码】**  
   这一步**只出清单，不删不改**。
4. Agent 逐条看：是不是同一主题、留哪份、怎么合成、矛盾听谁的。**【Agent】**
5. Agent 提交处理清单（合并谁、改写成什么、删谁）。**【Agent】**
6. 工具核对：只许动清单里的笔记；路径一碰到书就整单拒绝。**【代码】**
7. 执行删改。**【代码】**
8. 回报实际做了什么。**【代码】**
9. Agent 转述给你。**【Agent】**

**净化焊死的步：** 先扫描后动手；动手只限笔记。  
**Agent 干的：** 是不是同一条、留谁、合并后怎么写。

---


## 功能 6：自检

**谁用：** 你问「最近有没有可优化的」，或想加/减能力。  
**不管：** 工具自己根据数据改自己的代码。

### 场景 J：你问有没有值得优化的

1. 你问 Agent。**【人】**
2. Agent 调用「自检：查看」。**【Agent】**
3. 工具交出最近的调用和失败记录（大约一周），不改任何文件。**【代码】**
4. Agent 读完，问你几个问题，给建议。**【Agent】**

### 场景 K：你想加或减一个功能

5. Agent 按修理规范写提案：加还是减、动哪扇门、有没有风险。**【Agent】**
6. 你点头或否。**【人】**
7. 点头后先改说明书（`需求.md` / 本文），再考虑改程序。**【人 + Agent】**  
   第一版代码拒绝「直接补丁本工具源码」。**【代码】**

## 一张总表（对照用）

| 功能 | 输入 | 代码焊死的 | Agent 干的 | 输出 |
|---|---|---|---|---|
| 检索 | 「我想了解……」 | 只扫资料；先抬头后正文；条数/字数上限 | 问什么、要不要再读、怎么跟人说 | 路标；若再读则一段正文 |
| 阅读 | 哪一份的哪一块 | 必须有身份；一次一块；有字数顶 | 选读哪块 | 有限正文 |
| 收件箱入库 | 「把原始资料收进来」 | 全转、搬家、写成书的目录+导读 | 只负责点一下 | 成功/失败清单 |
| 指定入库 | 几个源文件路径 | 只转这几个；同样搬家 | 先自己找文件；找不到就别调 | 成功/失败清单 |
| 写笔记 | 一段 Markdown | 必须先看到类似条目；只进笔记；要有抬头 | 写什么、改旧还是开新 | 记下了 / 被拒绝原因 |
| 净化笔记 | 「整理笔记」 | 先清单后动手；动不了书 | 判断合并/删除/怎么写 | 整理报告 |
| 自检 | 「有没有可优化的」 | 只给记录，不改闸门和代码 | 解读、提问、写提案 | 建议或提案 |

---

## 明确不会发生的事

- 工具自己去网上找书、下载书
- 工具知道你在聊天里选了 B 还是 C
- 查询一次把三本书全文塞给 Agent
- 净化或写笔记改掉书的原文
- 人不经过 `原始资料/` 去改 `资料/` 里的文件（可以看，但不是正路；正路都经 Agent 调工具）
- 后台定时偷偷入库、偷偷净化（要做都由 Agent 点）

---

## 和「代码结合 Agent」怎么对上号

不是每一步都用代码算明白。  
是：**步骤由代码排好，Agent 不能抄近路；每一步上认字、判断、写句子，还是 Agent。**

---

## 卡壳了怎么办（所有门共用）

代码某一步做不下去时：**停，把情况交还给 Agent，不要自己死循环，也不要放开闸门让 Agent 抄近路。**

「Agent 接管」的意思是：它拿到一份明白的失败说明，改输入、换策略、或问你。  
不是：检索卡了就去把全书读进上下文；入库卡了就自己编一本；净化卡了就直接删文件。

### 每次失败必须带出来的信息

工具返回里至少要有这些（人话，给 Agent 看的）：

1. **卡在哪一步**（例如：收件箱入库-转换第 2 个文件）
2. **为什么**（文件打不开、不是 Markdown、想改书、没有点名身份……）
3. **已经做成了什么**（三本里两本成功，卡在第三本）
4. **Agent 可以怎么试**（换文件、补抬头、先检索再写、去问人）——只给仍走正门的办法，不给翻墙办法

### 几种常见卡壳

| 卡在哪 | 代码做什么 | Agent 接管做什么 |
|---|---|---|
| 检索没有像的 | 如实空结果，不要编 | 告诉你库里没有；不要装查过 |
| 阅读没给身份 / 一次要太多 | 拒绝，说明要先检索、一次一块 | 改成点名某一块再调 |
| 源文件转不成 Markdown | 这本失败，其它本继续；源文件先留在原始资料别丢 | 告诉你哪本坏了；坏的不要编书顶上 |
| 指定入库路径不对 | 拒绝，不动库 | 自己再找文件，或问你要文件 |
| 写笔记没先搜 / 格式不对 / 想写进书 | 拒绝并带上「已有的类似条目」或缺什么 | 补步骤或改内容后再交 |
| 净化清单想动书 | 整单拒绝，库不变 | 从清单里拿掉书，只处理笔记 |
| 工具自己崩了（意外错误） | 也当成失败交出去：哪一步、原始报错摘一句 | 告诉你「工具坏了，需要修」；不要换个姿势把同一错误再砸十次 |

同一条失败不要在工具里自动重试个没完。试一次、说清楚、交给 Agent。要再试，由 Agent 决定（换了输入再调），这样才修得及时，不会让一个错误闷着转圈。
