# 这个工具怎么干活（给人看的说明书）

> 现行规格是仓库根目录 `需求.md`。本文是同一套规则的白话步骤版。
> 写法尽量白话。
>
> 三个角色：
> - **人**：你。往规定文件夹丢文件、对 Agent 说话。
> - **Agent**：外面那个助手。真正去读、判断、写字、找书。
> - **代码**：本工具。不管理解内容，只管 **步骤走不走得过、手伸不伸得出去**。

一句话：人点名用这个库；Agent 来干活；代码规定它必须走哪些步、每一步只能拿到什么。

---

## 东西放哪

人碰的（工具检索时当没看见）：

- `原始资料/`：只准往这儿丢 PDF、EPUB、MOBI
- `原始资料归档/`：转成 Markdown 之后，源文件搬到这儿，不再动

工具检索只看：

- `资料/书/`：正式的书、长文。一部书一个文件夹，门口一份很短的「导读」（标题、几句话是干什么的、**顶层目录**）。正文切成若干**块**，一块一个自然篇/章。进库以后当原文，**不改、不净化**。超长篇阅读时开 8000 字窗口。
- `资料/笔记/`：心得、感悟、非书的东西。一份一个 Markdown。可以改、可以合并、可以删。

主题（心理学、矛盾论）不建文件夹，写在每份材料抬头那几句里。找的时候书和笔记一起找，不用跟工具说「去翻笔记」还是「去翻书」。

---

## 一共几扇门

Agent 能调的就这些（都要它来点，工具自己不会在后台偷跑）：

1. **检索** — 想了解什么，到库里去找
2. **收件箱入库** — 把已经丢在 `原始资料/` 里的，全部转成书
3. **指定入库** — 只把点名的那几个源文件转成书
4. **写笔记** — 把非书的文字写进笔记
5. **净化笔记** — 整理笔记（合并、更新、丢掉过期的），动不了书
6. **自检** — 看最近怎么被用、卡在哪；给建议；要改功能先写提案

下面每个功能：先说谁来用，再从输入走到输出，每一步标好谁干。

---

## 功能 1：检索

**谁用：** 你让 Agent 用这个库去谈一件事的时候。  
**外面不管：** 它为什么问、问完怎么跟你聊。  
**工具不管：** 书从哪买的、你选过哪本。

### 场景 A：你说「用这个库，给我讲讲拖延」

1. 你让 Agent 用这个工具，并说出想了解什么。**【人】**
2. Agent 调用「检索」，把那句话交进来。**【Agent】**
3. 工具拿问句去检索 `资料/`：正文和块名在**建库时**已切好词、写进一份**活在内存里的索引**（进程退出就没了，下次从正本重建）。查询时不读正本。**【代码】**
4. 按 bm25 打分，只留下最像的几条（数量有死上限）。**【代码】**
5. 还回去的是**路标**，分三栏：**两路都中（优先）/ 仅字面 / 仅地图**。重合由代码按身份算好。仅字面里很弱的命中不占那 5 个名额。建议块优先用地图「依据块」，概要题优先导读/地图。每本书报命中几块（只报数字）。**路标里一个字的正文都没有。**【代码】**
6. Agent 自己判断：够不够用、要不要跟你提书名、要不要再看原文。**【Agent】**
7. 够用就拿路标去跟你聊。**【Agent】**（工具不再管）

### 场景 B：它觉得要再看某一段或好几段

接着上面第 6 步，它决定加深。路标上会带着建议块（哪一章像），不是只说「有这本书」。

8. Agent 调用「阅读」，点名一块或多块（必须是有身份的，不能说「把心理学全给我」）。可以点章，也可以点章里的节名或偏移。多块就一次交清单。**【Agent】**
9. 工具只打开点名的那些块或节。每块、整次都有死上限；整本灌出来整单拒绝。某一块找不到，其它块照给，并写明做成了几块。末尾告诉邻块、本窗第几、这一章有哪些节。**【代码】**
10. Agent 拿到这几段，自己综合、决定怎么跟你说、提不提来源。**【Agent】**

### 场景 B2：交叉问题要两本书

你问一件跨两头的事（比如数学里的空间、物理里怎么用）。同一次检索的路标里可以同时出现两本书的建议章。Agent 一次点名两块，工具一次返回两块，都不是全书。**【代码 一次多块 / Agent 勾选和综合】**

### 场景 C：库里没有这事

1～5 同上，第 5 步是空的或很不像。**【代码】**  
6. 拉丁专名确实没有 → 如实空。生活题默认答案在库里，两路都弱也要给仅地图的最像项并标明，不许装没有。**【代码 空/最像 + Agent 转述】**

### 场景 D：书和笔记都会出现

你问「心理学」，库里既有一本教材，也有一条你以前的感悟。同一次检索里两条都可以作为路标出现，不用先选「搜书还是搜笔记」。**【代码 负责一起搜 / Agent 负责之后读哪条】**

### 场景 E：找到一段之后，要不要继续找

毛选这种书得读好几篇才敢下结论。Agent 读到一段后，要能自己判断**继不继续**：

11. 路标上带着**命中分布**：这一问命中多少块、分布在哪几卷。**【代码】**（只报数，不报正文）
12. Agent 看分布决定：够不够、要不要换个角度再检索、要不要顺着一块块读下去。**【Agent】**
13. 要读就照每次阅读末尾那行**邻块索引**（只有块名）点下一块；不要就停。**【Agent】**

**这一门的边界：工具只报「这本书命中多少块、建议哪几块、邻块是谁」，绝不替 Agent 说「你读够了」。** 窄问题读一块收工，宽问题才铺开——**不鼓励为了保险把整本读完**。这是 Agent 的克制，不是工具限轮次。

**检索这一门，代码焊死的步：** 只回身份和命中理由、永不回正文；正文必须点名；一次可以多块，但块数和总字数有顶；一次不能拿走整本。  
**Agent 干的：** 问什么、勾选哪几块、要不要加深、怎么跟人说。

## 功能 2：收件箱入库

**谁用：** 你已经把书丢进 `原始资料/`，让 Agent「把里面的收进库」。  
**不管：** 文件是谁下载的。工具只处理文件夹里已经有的。

### 场景 E：你丢了三本，让它入库

1. 你把 PDF/EPUB/MOBI 放进 `原始资料/`。**【人】**
2. 你对 Agent 说：把原始资料入库。**【人】**
3. Agent 调用「收件箱入库」（不用报书名）。**【Agent】**
4. 工具把这个文件夹里**所有**待处理的源文件，一本本转成 Markdown。**【代码】**
5. 转好的放进 `资料/书/`：导读（来自书）+ **地图.md（能解决什么，派生）** + 各块。缺地图不算这本入完。**【代码 + 必要时 Agent 按模板补地图】**
6. 源文件从 `原始资料/` 搬到 `原始资料归档/`。**【代码】**
7. 告诉 Agent：成功几本、哪本失败了。**【代码】**
8. Agent 转述给你。**【Agent】**

转格式、搬家、切块、写导读抬头，都是工具自己做。

**切块硬要求：一块一个自然篇/章，块名来自书里。** 有 markdown 标题就认到三级（毛选的篇）；整篇一个 `#` 都没有，才把「第一章 …」「一、」当切点——有标题时不要用「一、」把正文撕成清单。超长篇不预切成 4K 文件，阅读时用显式窗口。**切完要数字数：各块正文之和不得少于转换产物的 99%**，不许切丢字。

Agent 不许跳过转换、直接拿 PDF 去检索，也不许改归档里的源文件。

## 功能 3：指定入库

**谁用：** 你说「把 B、C 两本放进库」；文件可能还不在收件箱里。  
**和收件箱的差别：** 只收点名的文件，不把收件箱里其它东西一锅端。  
**工具仍然不找书。** 找不到是 Agent 的事。

### 场景 F：推荐了三本，你选 B、C

1. 你们聊天选出 B、C。**【人 + Agent】**（工具看不见这场聊天）
2. Agent 自己去找这两本的源文件。**【Agent】**
3. 找不到：告诉你，**不要**调用入库。**【Agent】**
4. 找到了：调用「指定入库」，交上文件路径（或已经丢进 `原始资料/` 的文件名）。**【Agent】**
5. 工具**只转这几个文件**，其它待处理的不动。**【代码】**
6. 和收件箱入库一样：Markdown 进 `资料/书/`，源文件进归档。**【代码】**
7. 回报成功/失败。**【代码】**
8. Agent 告诉你入库了。**【Agent】**  
   工具只知道「又进了两份合法的书」，不知道这是你选的 B、C。

指定的是**文件**，不是书名。对工具说「去弄一本《思考快与慢》」不算指定入库，那是找书，工具拒绝或根本没有这种叫法。

## 功能 4：写笔记

**谁用：** 非书的东西——你的感悟、讨论里要留下的话、Agent 整理的心得。更自由，但只能进笔记，不能冒充一本书。

### 场景 G：你说「把刚才那句记下来」（感悟）

1. 你让记一条笔记。**【人】**
2. Agent 写成 Markdown，调用「写笔记：预览」。**【Agent】**
3. **强制先搜：** 工具用同一套检索，把类似的路标扔回去。**【代码】**  
   这一步跳不过。
4. Agent 判断：是改旧的一条，还是确实该新开一条。**【Agent】**
5. 感悟、判断：求证结论填 `非事实`，不必翻书。**【Agent】**
6. Agent 调用「写笔记：求证」，再 create 或 update。**【Agent】**
7. 工具检查：预览过、求证过、是 Markdown、只进笔记、有抬头、动不了书。**【代码】**
8. 过了就写入；不过就拒绝。**【代码】**
9. Agent 告诉你记好了或没记下。**【Agent】**

### 场景 G2：记下一条读书笔记（要对照书）

接着检索和阅读。Agent 已经用「阅读」拿过依据章节（可以一次多块）。

1. 预览类似条目。**【代码 强制 / Agent 点】**
2. 求证结论填 `相符` 或 `部分不符`，并列出依据身份。**【Agent】**
3. 工具核对：这些身份在库里，而且调用日志里已经成功阅读过。没读过就声称相符，拒绝。**【代码】**
4. 通过才写入。书原文不动；对不上就标 `部分不符`，不许改书。**【代码】**

### 场景 G3：没读就声称「根据某章」

预览之后直接 create，或求证填 `相符` 但日志里没有读过那些身份。**【代码 拒绝】**  
Agent 应先点名阅读，再求证。

### 场景 H：它想把一本「假书」当书写进去

走写笔记却想写到 `资料/书/`，或指定入库却交来一段自己编的正文、没有源文件。**【代码 直接拒绝】**  
书只从源文件转换来。

## 功能 5：净化笔记

**谁用：** 你让整理笔记，或 Agent 觉得笔记该打扫了。  
**只打扫笔记。** 书、归档、原始资料一律不动。  
**不在后台自己跑**，每次都要 Agent 来点一下。

### 场景 I：你说「把笔记整理一下」

1. 你让整理，或 Agent 决定该净化了。**【人 或 Agent】**
2. Agent 调用「净化：先扫描」。**【Agent】**
3. 工具只扫 `资料/笔记/`，列出可疑项，例如：标题很像的好几条、太短、没抬头、已经标过期、明显重复。**【代码】**  
   这一步**只出清单，不删不改**。
4. Agent 逐条看：是不是同一主题、留哪份、怎么合成、矛盾听谁的。**【Agent】**
5. Agent 提交处理清单（合并谁、改写成什么、删谁）。**【Agent】**
6. 工具核对：只许动清单里的笔记；路径一碰到书就整单拒绝。**【代码】**
7. 执行删改。**【代码】**
8. 回报实际做了什么。**【代码】**
9. Agent 转述给你。**【Agent】**

**净化焊死的步：** 先扫描后动手；动手只限笔记。  
**Agent 干的：** 是不是同一条、留谁、合并后怎么写。

## 功能 6：自检

**谁用：** 你问「最近有没有可优化的」，或想加/减能力。  
**不管：** 工具自己根据数据改自己的代码。

### 场景 J：你问有没有值得优化的

1. 你问 Agent。**【人】**
2. Agent 调用「自检：查看」。**【Agent】**
3. 工具交出最近的调用和失败记录（大约一周），不改任何文件。**【代码】**
4. Agent 读完，问你几个问题，给建议。**【Agent】**

### 场景 K：你想加或减一个功能

5. Agent 按修理规范写提案：加还是减、动哪扇门、有没有风险。**【Agent】**
6. 你点头或否。**【人】**
7. 点头后先改说明书（`需求.md` / 本文），再考虑改程序。**【人 + Agent】**  
   第一版代码拒绝「直接补丁本工具源码」。**【代码】**

## 一张总表（对照用）

| 功能 | 输入 | 代码焊死的 | Agent 干的 | 输出 |
|---|---|---|---|---|
| 检索 | 「我想了解……」 | 只回身份和命中理由、永不回正文；路标最多 5 条，带命中块数；索引只在内存 | 问什么、勾选哪几块、要不要继续 | 路标（含建议块与块数） |
| 阅读 | 一块或多块的身份 | 必须有身份；最多 5 块；单块 8k（兜底）、整次 24k；整本整单拒绝；缺一块其它照给；末尾附邻块索引 | 选读哪几块、要不要续读 | 有限正文，按块贴来源＋邻块名 |
| 收件箱入库 | 「把原始资料收进来」 | 全转、按自然篇切块、搬家、写成书的目录+导读、字数守恒 | 只负责点一下 | 成功/失败清单 |
| 指定入库 | 几个源文件路径 | 只转这几个；同样搬家 | 先自己找文件；找不到就别调 | 成功/失败清单 |
| 写笔记 | 一段 Markdown | 必须预览 → 求证 → 写入；只进笔记；要有抬头；`相符`/`部分不符` 必须先读过依据 | 写什么、改旧还是开新、真假怎么判 | 记下了 / 被拒绝原因 |
| 净化笔记 | 「整理笔记」 | 先清单后动手；动不了书 | 判断合并/删除/怎么写 | 整理报告 |
| 自检 | 「有没有可优化的」 | 只给记录，不改闸门和代码 | 解读、提问、写提案 | 建议或提案 |

## 明确不会发生的事

- 工具自己去网上找书、下载书
- 工具知道你在聊天里选了 B 还是 C
- 查询一次把三本书全文塞给 Agent（一次多块也只给点名的章，有总顶）
- 搜索结果带正文摘录，或按问句自动灌命中章
- 路标里出现正文（一个字的正文都不许有）
- 工具替 Agent 说「你读够了」（只报还有多少、哪些已读）
- 索引落盘成文件或数据库（索引只在进程内存里活）
- 书里有的内容却搜不到（切完要抽查回捞，见 `docs/验收标准.md`）
- 块大到读不完（超长篇必须能用显式窗口读完）
- 写笔记不求证就落盘，或没读过就声称根据某章
- 净化或写笔记改掉书的原文
- 人不经过 `原始资料/` 去改 `资料/` 里的文件（可以看，但不是正路；正路都经 Agent 调工具）
- 后台定时偷偷入库、偷偷净化（要做都由 Agent 点）

---

## 和「代码结合 Agent」怎么对上号

不是每一步都用代码算明白。  
是：**步骤由代码排好，Agent 不能抄近路；每一步上认字、判断、写句子，还是 Agent。**

---

## 卡壳了怎么办（所有门共用）

代码某一步做不下去时：**停，把情况交还给 Agent，不要自己死循环，也不要放开闸门让 Agent 抄近路。**

「Agent 接管」的意思是：它拿到一份明白的失败说明，改输入、换策略、或问你。  
不是：检索卡了就去把全书读进上下文；入库卡了就自己编一本；净化卡了就直接删文件。

### 每次失败必须带出来的信息

工具返回里至少要有这些（人话，给 Agent 看的）：

1. **卡在哪一步**（例如：收件箱入库-转换第 2 个文件）
2. **为什么**（文件打不开、不是 Markdown、想改书、没有点名身份……）
3. **已经做成了什么**（三本里两本成功，卡在第三本）
4. **Agent 可以怎么试**（换文件、补抬头、先检索再写、去问人）——只给仍走正门的办法，不给翻墙办法

### 几种常见卡壳

| 卡在哪 | 代码做什么 | Agent 接管做什么 |
|---|---|---|
| 检索没有像的 | 如实空结果，不要编 | 告诉你库里没有；不要装查过 |
| 阅读没给身份 / 一次要整本 | 整单拒绝，说明要先检索、点名块 | 改成身份列表再调 |
| 阅读清单里某一块找不到 | 这一块失败，其它块照给 | 对照路标改那一块的名字 |
| 源文件转不成 Markdown | 这本失败，其它本继续；源文件先留在原始资料别丢 | 告诉你哪本坏了；坏的不要编书顶上 |
| 指定入库路径不对 | 拒绝，不动库 | 自己再找文件，或问你要文件 |
| 写笔记没先搜 / 没求证 / 格式不对 / 想写进书 | 拒绝并带上缺哪一步 | 补预览或求证，或改内容后再交 |
| 写笔记声称相符但没读过依据 | 拒绝 | 先阅读那些身份，再求证 |
| 净化清单想动书 | 整单拒绝，库不变 | 从清单里拿掉书，只处理笔记 |
| 工具自己崩了（意外错误） | 也当成失败交出去：哪一步、原始报错摘一句 | 告诉你「工具坏了，需要修」；不要换个姿势把同一错误再砸十次 |

同一条失败不要在工具里自动重试个没完。试一次、说清楚、交给 Agent。要再试，由 Agent 决定（换了输入再调），这样才修得及时，不会让一个错误闷着转圈。
